# Сравнение политических позиций

> Историческая спецификация анализа политического согласия. Текущий веб-раздел
> переведён на [локальные эмбеддинги комментариев](adr/0003-local-comment-embeddings.md)
> и показывает сходство текстов без определения политического согласия.


Статус: реализовано после подтверждения общего понимания.

## Согласованные требования

- Сравнивать только политические позиции по конкретным вопросам.
- Выделять вопросы автоматически из комментариев; не объединять разные предметы обсуждения только на основании похожести текста.
- Для автора использовать последнюю по дате ясно выраженную позицию с датой и подтверждающим высказыванием.
- Сохранять неоднозначные высказывания, но исключать их из определения позиции и оценки.
- Сравнивать только вопросы, по которым оба автора выразили позицию. Отсутствие позиции не означает нейтральность, согласие или расхождение.
- При неясном отношении двух позиций исключать вопрос из оценки.
- Все сравнимые вопросы имеют одинаковый вес, независимо от числа комментариев.
- Различать совпадение, частичное совпадение и расхождение; сохранять объяснение условий и оговорок.
- Оценка согласия: `100 × (совпадения + 0,5 × частичные совпадения) / число сравнимых вопросов`. При нулевом числе сравнимых вопросов оценка не определена.
- Для рейтинга требуются минимум три сравнимых вопроса. При меньшем охвате показывать найденные совпадения отдельно с пометкой «Недостаточно данных для рейтинга».
- Считать эмбеддинги локально, анализировать вопросы и позиции через DeepSeek. Сохранять результаты; при неизменных настройках обрабатывать только новые комментарии.
- Модель эмбеддингов первой версии — `intfloat/multilingual-e5-base`, с зафиксированной ревизией. Сохранённые эмбеддинги привязывать к этой ревизии.

## Интерфейс

На странице пользователя показать раздел «Близкие политические позиции» с десятью ближайшими авторами среди уже собранных пользователей.

Для выбранного автора рассматривать всех собранных пользователей. Не отбирать пользователей для сравнения по среднему эмбеддингу их комментариев; эмбеддинги используются для поиска близких формулировок политических вопросов, а рейтинг строится по подтверждённому отношению позиций.

Для каждой пары показать оценку согласия, количество сравнимых вопросов и количества совпадений, частичных совпадений и расхождений. По нажатию открыть подробное сравнение: вопросы, объяснения, даты и исходные комментарии обоих авторов.

Сортировать рейтинг по убыванию оценки согласия. При одинаковой оценке выше ставить автора с большим количеством сравнимых вопросов; при одинаковых оценке и количестве применять стабильный порядок по Telegram ID.

При недостаточном охвате показывать найденные совпадения отдельно от рейтинга.

## Запуск анализа

Кнопка «Найти близкие позиции» запускает анализ в фоне с отображением прогресса. Обращения к DeepSeek выполняются при явном запуске анализа.

Первый запуск анализирует всю собранную историю комментариев, без ограничения последними сообщениями или временным окном. Для сравнения выбирается последняя ясно выраженная позиция по каждому вопросу; её дата показывается в результате.

Повторный запуск обрабатывает новые комментарии и затронутые ими сравнения, используя сохранённые результаты при неизменных настройках. Готовые результаты доступны без повторного анализа. Последний завершённый рейтинг остаётся видимым во время обновления и после его сбоя, включая запуск той же версии; прогресс и ошибка относятся к текущему запуску.

## Сбои и неполные результаты

При сбое DeepSeek сохранять прогресс. Повторный запуск продолжает обработку с места остановки, не анализируя повторно уже успешно обработанные комментарии при неизменных настройках.

Если часть истории ещё не обработана, показывать результат как неполный с количеством обработанных комментариев. Сравнения, затронутые необработанной историей, не включать в рейтинг завершённых сравнений.

## Версии анализа

Привязывать результаты к версиям модели и правил анализа. При их изменении сохранять старый результат с пометкой «Требуется обновление»; пересчёт новой версией запускается кнопкой.

Старые и новые версии анализа не смешивать в одной оценке. Не выполнять платный пересчёт автоматически при изменении версии.

## Инженерные детали для реализации

- Извлечение выполняется пакетами до 8 комментариев и до 16 тысяч символов суммарно (длинный одиночный комментарий обрабатывается целиком). При исчерпании лимита ответа или нарушении контракта пакет делится; успешные части сохраняются отдельно. Невалидный одиночный ответ сохраняется без позиции с причиной исключения, чтобы не останавливать корпус и не повторять платный запрос. В прогрессе показывается количество исключённых комментариев. Тексты не обрезаются; вход больше 60 тысяч символов исключается с причиной `comment_too_long`. Транспортные ошибки, HTTP-сбои, битый JSON и прерванная генерация (включая `insufficient_system_resource`, `aborted` и неизвестные `finish_reason`) не превращаются в исключённые комментарии: запуск останавливается, анализ можно продолжить. `content_filter` исключается с отдельной причиной; `length` уменьшает пакет. Нарушения схемы, идентификаторов и цитат сохраняются с отдельными причинами `invalid_schema`, `invalid_ids`, `quote_mismatch`; старые исключения `invalid_contract` сохраняются; старые записи `invalid_response` повторно проверяются при явном запуске без сброса остальных результатов. Каждое деление пакета логируется с размером и безопасным кодом причины без исходного текста.
- Порог уверенности извлечённой позиции — 0,8. Неоднозначные комментарии сохраняются в контрольных точках без позиции.
- E5 кодирует формулировки вопросов с префиксом `query: `, усреднением скрытых состояний и нормализацией L2. Ревизия — `d128750597153bb5987e10b1c3493a34e5a4502a`, пакет до 16 формулировок, CPU или доступная CUDA.
- Для каждого нового вопроса проверяются до 8 ближайших представителей уже выделенных вопросов; решение об объединении принимает DeepSeek. Это приближённый поиск и не гарантирует полного выявления общих вопросов. Сохранённые представители стабильны при поступлении новых комментариев.
- Если различающиеся позиции одного автора имеют одинаковую последнюю дату, вопрос исключается из сравнения до появления более поздней ясной позиции.
- DeepSeek вызывается через OpenRouter (`OPENROUTER_API_KEY`) с JSON-выводом и `reasoning.enabled=false`. Модель по умолчанию — `deepseek/deepseek-v4-flash-0731` (`OPENROUTER_MODEL`), маршрут — `deepinfra/fp8` (`OPENROUTER_PROVIDER`), без fallback. Кэш привязан к адресу API, модели, маршруту, параметрам запроса, правилам, ревизии эмбеддингов и `POSITION_ANALYSIS_GENERATION`. Возвращаемые имя модели, провайдер и fingerprint проверяются, чтобы не смешивать обнаруженные версии провайдера.
- Данные анализа сохраняются в отдельной SQLite; успешно обработанные пакеты и проверки записываются сразу. Межпроцессный файловый lock разрешает только один анализ одновременно.
- API: `POST /api/v1/position-analysis` запускает фоновой анализ; `GET /api/v1/users/{db_name}/position-comparisons` возвращает результаты и прогресс.

## Уточнения после ревью

- В сравнение передаются канонический вопрос и исходные формулировки обоих авторов; остальные темы исходного комментария не участвуют в оценке.
- Extraction кешируется по точному тексту без контекста канала. Неоднозначные внешние ссылки должны приводить к отсутствию позиции.
- При обнаруженной смене модели/fingerprint сохраняется состояние `provider_changed`; повторный запуск заблокирован до изменения поколения, без новых оплаченных запросов в старой версии.
- SQLite работает в WAL; комментарии читаются пакетно, embeddings — только для нужных ключей пачками до 500, группы вопросов сохраняются отдельными строками. Чтение источников, подготовка кеша и запись контрольных точек выполняются вне event loop. При отмене анализ ждёт завершения записи перед освобождением lock.
- Фоновая задача получает уже захваченную блокировку; отмена до старта задачи также освобождает её. HTTP-клиент DeepSeek переиспользуется в пределах одного запуска.

- Сохранённая identity провайдера читается один раз на запуск и проверяется в памяти на каждом успешном ответе. При новом запуске повторно читается значение из SQLite, чтобы учитывать другой процесс.

- Панель прогресса различает извлечение комментариев, создание эмбеддингов, сопоставление вопросов и сравнение позиций. Процент показывает выполнение текущего этапа. Для сравнения отдельно считаются отношения по вопросам и завершённые пары авторов. Показываются текущая операция, время обновления, кеш, число запросов и делений пакетов, причины исключений.
- Эмбеддинги создаются после извлечения позиций из всей истории: локальный E5 сохраняет 768 чисел в JSON-массиве, нормализованном по L2, в таблице `cache`, namespace `embeddings:<версия модели>`. API и раскрывающийся блок панели возвращают модель, размерность, путь хранилища и количество сохранённых векторов.
