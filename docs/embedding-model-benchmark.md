# Сравнение локальных моделей эмбеддингов

Дата замеров: 2026-10-09. Сравниваются четыре модели на тех же комментариях,
запросах и разметке, что и в
[embedding-chunking-research.md](embedding-chunking-research.md). Меняется только
модель.

## Итог

Различия в качестве между моделями не выходят за шум замеров: ни одна модель
не лучше `multilingual-e5-base` ни по одной метрике достоверно. Поэтому
рекомендуется самая простая и быстрая — **`intfloat/multilingual-e5-small`**:
вектор 384 вместо 768, расчёт в 2,7–3 раза быстрее, вдвое меньше памяти.

Рекомендация принята 2026-10-09: рабочая модель — `multilingual-e5-small`,
миграция `0005` перевела столбцы эмбеддингов на `vector(384)`, оба уровня
эмбеддингов построены для всей базы. Фактические время, объём и скорость поиска —
в разделе «После выбора».

## Что сравнивалось

| | |
|---|---|
| Комментарии | 44 314 комментариев 15 профилей |
| Запросы | 22, релевантных сообщений 2 669; разметка та же |
| Стратегия A | одно сообщение — один вектор, 44 314 векторов |
| Стратегия C | чанки до 256 токенов внутри канала, без перекрытия, 4 733 вектора |
| Поиск | точный перебор среди векторов одного пользователя, без индекса |
| Оборудование | RTX 3060 12 ГБ, точность float32 у всех моделей |

Чанки построены один раз, токенизатором `multilingual-e5-base`, поэтому все
модели кодируют одни и те же тексты. Векторы хранятся в файлах
`data/benchmark`, в таблицы PostgreSQL не пишутся: модели разной размерности
сравниваются без изменения схемы.

## Как применялась каждая модель

Взято из карточек моделей и их конфигурации `1_Pooling/config.json`.

| Модель | Ревизия | Текст | Запрос | Объединение | Нормализация | Предел входа |
|---|---|---|---|---|---|---|
| `intfloat/multilingual-e5-small` | `614241f622f5` | `passage: ` | `query: ` | среднее по маске | L2 | 512 |
| `intfloat/multilingual-e5-base` | `d12875059715` | `passage: ` | `query: ` | среднее по маске | L2 | 512 |
| `BAAI/bge-m3` | `5617a9f61b02` | без префикса | без инструкции | токен `[CLS]` | L2 | 8192 |
| `Qwen/Qwen3-Embedding-0.6B` | `97b0c614be4d` | без префикса | `Instruct: <задача>\nQuery:` | последний токен, дополнение слева | L2 | 8192 |

- **BGE-M3**: используется только плотный вектор. Карточка прямо говорит, что
  инструкция к запросу этой модели не нужна.
- **Qwen3**: карточка требует одну фразу с описанием задачи перед запросом и
  советует писать её по-английски. Использована
  `Given a topic, retrieve comments that discuss it`. Предел входа взят 8192, как
  в примере карточки, хотя модель принимает до 32 тысяч токенов. Нужен
  `transformers` не старше 4.51.
- **Точность.** Карточки E5 точность не оговаривают. Для BGE-M3 примеры
  предлагают половинную точность ради скорости «с небольшой потерей качества»,
  карточка Qwen3 советует `flash_attention_2`. Все модели запущены в float32,
  чтобы сравнение было на равных; с половинной точностью BGE-M3 и Qwen3 были бы
  быстрее и заняли бы меньше памяти, это не измерялось.

### Значимы ли различия

Разница с `multilingual-e5-base` по каждому запросу, среднее и 95-процентный
интервал (бутстреп по 22 запросам, 10 000 повторов). Интервал, содержащий ноль,
означает, что различие не показано.

| Модель | Стратегия | R@5 | R@10 | MRR | NDCG@10 |
|---|---|---|---|---|---|
| e5-small | A | +0,003 [−0,008; +0,014] | −0,007 [−0,021; +0,003] | +0,041 [−0,066; +0,156] | +0,015 [−0,066; +0,099] |
| e5-small | C | −0,001 [−0,018; +0,017] | −0,004 [−0,016; +0,009] | 0,000 [−0,083; +0,098] | −0,039 [−0,088; +0,008] |
| bge-m3 | A | 0,000 [−0,011; +0,011] | −0,003 [−0,013; +0,008] | +0,015 [−0,149; +0,183] | −0,027 [−0,103; +0,050] |
| bge-m3 | C | −0,001 [−0,012; +0,010] | −0,002 [−0,016; +0,014] | +0,017 [−0,016; +0,068] | −0,023 [−0,078; +0,029] |
| Qwen3 | A | +0,012 [0,000; +0,026] | +0,010 [−0,002; +0,023] | +0,047 [−0,057; +0,152] | +0,081 [−0,002; +0,159] |
| Qwen3 | C | −0,008 [−0,024; +0,005] | −0,009 [−0,022; +0,004] | −0,044 [−0,102; 0,000] | −0,028 [−0,064; +0,009] |

- Все 24 интервала содержат ноль или касаются его.
- Ближе всех к отличию Qwen3 на уровне сообщений: R@5 +0,012 и NDCG@10 +0,081,

  MRR −0,044, интервал тоже упирается в ноль. Устойчивого преимущества нет.
- Ширина интервалов по MRR — до ±0,15. Двадцати двух запросов недостаточно,
  чтобы различить модели, если разница между ними меньше этого.

## Короткие реплики

Небольшая ручная проверка, не замер. Взято 10 сообщений короче 10 токенов из
переписки и для каждого по окружающим сообщениям сформулирован запрос о теме
разговора. Смотрится место самого сообщения среди сообщений пользователя и место
чанка, в который оно входит, среди чанков пользователя.

Восемь случаев — реплики, смысл которых задаёт только контекст: «да» (дважды),
«+», «бред», «согласен» (дважды), «именно», слово чатового жаргона.

| Модель | Одиночное сообщение: медиана места | В первой сотне | Чанк: медиана места | Чанк в первой десятке |
|---|---|---|---|---|
| e5-small | 48 % списка | 0 из 8 | 1,4 % списка | 4 из 8 |
| e5-base | 24 % списка | 0 из 8 | 0,4 % списка | 5 из 8 |
| bge-m3 | 29 % списка | 1 из 8 | 0,5 % списка | 5 из 8 |
| Qwen3 | 38 % списка | 0 из 8 | 1,1 % списка | 4 из 8 |

- Одиночная реплика такого рода не находится ни одной моделью: она стоит в
  середине списка из 24 тысяч сообщений, то есть на случайном месте.
- Тот же текст внутри чанка находится: у всех моделей чанк в половине случаев
  попадает в первую десятку. Это свойство нарезки, а не модели.
- Два-три случая из восьми остаются далеко и через чанк, за сотым местом. В них
  чанк собран из 26–42 мелких реплик на разные темы, и тема разговора в нём
  теряется.

Два случая — короткие, но самостоятельные высказывания из трёх-четырёх слов.
Одиночными они находятся хорошо у всех моделей (места от 4 до 143 из 24 тысяч), а
в составе чанка один из них уходит вниз: места 17, 177, 747 и 737. Короткое
сообщение с собственным содержанием чанк разбавляет.

Слово «ага» встречается в этих комментариях один раз, «бред» — дважды,
«согласен» — восемь раз; случай с «ага» не использован.

Вывод тот же, что в отчёте о нарезке: нужны оба уровня, и модель на это не
влияет.

## Ограничения

- Разметка лексическая: сообщение релевантно, если совпадает с регулярным
  выражением темы, плюс 20 ручных добавлений. Доля ложных совпадений не
  измерена. Ручные добавления взяты из выдачи `multilingual-e5-base` и слегка
  ей подыгрывают.
- R@5 и R@10 малы по построению: на запрос приходится от 17 до 305 релевантных
  сообщений.
- NDCG@10 между стратегиями A и C несопоставим; между моделями внутри одной
  стратегии сопоставим.
- Запросов 22. Для BGE-M3 и Qwen3 инструкция и точность выбраны один раз, без
  подбора.
- Чанки нарезаны токенизатором E5. Для Qwen3 те же тексты занимают другое число
  токенов, но до предела входа им далеко.
- `OPI-PIB/EuroDense-435M`, названная как возможный кандидат, не запускалась:
  она загружается только с выполнением кода из репозитория модели
  (`trust_remote_code`), а в проекте это отключено. В окончательный список
  моделей она не вошла.

## Рекомендация

1. **Лучшая по качеству.** Не определена: различия в пределах шума. Номинально
   на уровне сообщений впереди Qwen3, на чанках — BGE-M3.
2. **Лучшая по соотношению качества и скорости.** `multilingual-e5-small`: по
   качеству неотличима от остальных, в 2,7–3 раза быстрее базовой E5, в 8–9 раз
   быстрее BGE-M3 и в 19–21 раз быстрее Qwen3.
3. **Есть ли выигрыш относительно `e5-base`.** Нет, ни у одной модели.
4. **Оставлять ли `e5-base`.** Замеры оснований для этого не дают. Единственный
   довод — ею уже считает раздел сравнения авторов, но его векторы хранятся
   отдельно, в `analysis_cache`, и совместно не используются.
5. **Переходить ли на `e5-small`.** Да.
6. **Использовать ли BGE-M3 или Qwen3.** Нет: втрое и всемеро медленнее базовой
   E5, векторы на треть длиннее, Qwen3 занимает 7,9 ГБ памяти GPU из 12, а
   выигрыш не показан.
7. **Рабочая модель по умолчанию.** `intfloat/multilingual-e5-small`, ревизия
   `614241f622f53c4eeff9890bdc4f31cfecc418b3`.

### Что это означает для схемы

| | `e5-small` | `e5-base`, как сейчас |
|---|---|---|
| Размерность | 384 | 768 |
| Нужна ли миграция | да: столбцы `vector(768)` в `message_embeddings` и `chunk_embeddings` заменить на `vector(384)` | нет |
| Объём, профили (44 314 сообщений и 4 733 чанка) | около 80 МБ | около 160 МБ |
| Объём, вся база (110 585 сообщений и чанки) | около 200 МБ | около 390 МБ |
| Расчёт, профили | 27 с | 77 с |
| Расчёт, вся база | около минуты | около трёх минут |

Объём оценён из размера вектора (4 байта на число плюс заголовок строки и
первичный ключ), а не измерен на рабочих таблицах. Время для всей базы
пересчитано из скорости на профилях.

Таблица выше — оценка, сделанная до построения. Что получилось на деле, см. ниже.

## После выбора

Миграция `0005` удалила 465 пробных векторов `e5-base` и изменила тип столбцов.
Затем для всей базы построены чанки (`token_budget`, 256 токенов, внутри канала,
без перекрытия) и оба уровня эмбеддингов.

| | Строк | Время | Объём |
|---|---|---|---|
| чанки, 9 858 пользователей | 24 489 | 64 с | 25 МБ и 13 МБ связей |
| эмбеддинги сообщений | 110 585 | 248 с | 176 МБ |
| эмбеддинги чанков | 24 489 | 98 с | 39 МБ |

- **Время втрое-вчетверо больше оценки.** Оценка «около минуты» учитывала только
  работу модели. Рабочий конвейер читает тексты из базы пакетами по 256 и пишет
  векторы обратно; процесс при этом занят на одном ядре процессора, а не на GPU.
  Всего 5 минут 46 секунд на оба уровня — 445 сообщений и 250 чанков в секунду.
- **Объём близок к оценке:** 215 МБ на оба уровня против оценённых 200 МБ, около
  1,6 КБ на вектор.
- **Повторный запуск** ничего не добавляет: 0 чанков, 0 векторов.
- **Проверки:** у каждого сообщения и каждого чанка есть вектор, векторов без
  владельца нет, размерность у всех 384, нормы 1,0000, в `embedding_models` одна
  строка с ревизией `614241f622f53c4eeff9890bdc4f31cfecc418b3`.

Точный поиск на рабочих таблицах, 22 запроса по три раза, внутри пользователя:

| Уровень | p50, мс | p95, мс | Максимум, мс |
|---|---|---|---|
| сообщения | 19,9 | 57,4 | 80,8 |
| чанки | 3,5 | 5,9 | 6,5 |

Первая десятка из базы совпала с прямым перебором тех же векторов во всех шести
проверенных запросах, на обоих уровнях. Индекс HNSW не создавался.

## Как повторить

```
python -m benchmarks.model_benchmark --no-cache   # все модели и таблица
python -m benchmarks.model_benchmark --report     # только таблица
python -m benchmarks.model_benchmark --short-check
```

Нужны PyTorch с CUDA, `transformers` не старше 4.51 и локальные файлы
`benchmarks/eval/mapping.local.json` и `data/benchmark/short_cases.local.json`,
которых нет в репозитории: в них настоящие идентификаторы сообщений.
